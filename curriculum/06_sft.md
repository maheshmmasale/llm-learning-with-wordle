# Module 6 — Supervised Fine-Tuning a Small Language Model

## Why this module matters

This module tests whether a 0.2B–0.5B model can internalize useful Wordle behavior from solver-generated data. The objective is not merely to reduce training loss. You must connect optimization choices to held-out game performance, distinguish imitation from memorization, and compare parameter-efficient adaptation with full fine-tuning under a fixed compute budget.

## Learning objectives

By the end of this module, you should be able to:

- Select and load a suitable small open model and tokenizer.
- Format state-action examples consistently with inference prompts.
- Run LoRA and, when feasible, full-parameter fine-tuning.
- Track training loss, validation loss, game metrics, and compute use.
- Use held-out and challenge splits to detect memorization.
- Compare base, prompted, SFT, and SFT-plus-search systems fairly.
- Save reproducible checkpoints, adapters, and model cards.

## Model and method choices

Candidate model families include [SmolLM 360M](https://huggingface.co/HuggingFaceTB), [Qwen2 0.5B](https://huggingface.co/Qwen), and [TinyLlama](https://huggingface.co/TinyLlama) if a slightly larger model is allowed. Record the exact repository, revision, license, parameter count, context length, and chat template. Do not switch models after inspecting test performance.

Start with LoRA because it is cheap and makes iteration practical. Sweep rank, target modules, learning rate, effective batch size, warmup, sequence length, and number of epochs conservatively. If hardware permits, run one matched full-fine-tune baseline. Equalize training tokens or report the difference clearly.

## Training protocol

Create one serialized format for training and evaluation. Mask padding and, if appropriate, prompt tokens so the loss focuses on the answer. Validate truncation: silently dropping the latest feedback makes examples incorrect. Log tokens processed, optimizer steps, precision, GPU type, wall time, peak memory, and estimated monetary cost.

Select hyperparameters on validation game performance, not only token loss. Evaluate fixed checkpoints during training to detect overfitting. Preserve the frozen Module 2 benchmark and run the final test once after choosing the configuration.

Anti-memorization controls should include answer-disjoint splits, shuffled or paraphrased state representations, uncommon and repeated-letter challenge sets, and tests on legal states not generated by the teacher’s normal trajectory. Compare action accuracy against the teacher with actual game win rate; they are related but not identical.

## Suggested experiments

1. LoRA ranks such as 4, 8, 16, and 32 under equal token budgets.
2. LoRA versus full fine-tuning on the same data subset.
3. Dataset sizes of 10K, 100K, and larger only if justified.
4. Single-action targets versus top-`k` or score-aware supervision.
5. Raw history versus canonical constraints in the training format.
6. One, two, and several epochs while monitoring challenge performance.
7. SFT alone versus SFT with deterministic filtering or search.
8. A control trained on shuffled action labels to verify the pipeline is not leaking targets.

## Questions to answer

- Does lower validation loss predict better Wordle win rate?
- What does SFT improve: legality, constraint tracking, strategic choice, or formatting?
- Does LoRA reach full-fine-tune quality per unit compute?
- Which examples are memorized, and which behaviors generalize?
- How sensitive is the result to prompt format at inference?
- Does search still help after training, and is that gain complementary?

## Deliverables

- Reproducible training configs and a one-command training entry point.
- At least one LoRA adapter and, if feasible, one full-fine-tuned checkpoint.
- Training curves, validation game curves, resource logs, and cost accounting.
- A table comparing base, prompted, SFT, and SFT-plus-search systems.
- Held-out, challenge, and anti-leakage evaluation results.
- A model card describing base model, dataset, procedure, intended use, limitations, and exact reproduction instructions.
- A brief failure analysis with representative trajectories before and after SFT.

**Exit criterion:** the observed improvement survives held-out evaluation and cannot plausibly be explained by target leakage, formatting changes, or extra inference compute.
